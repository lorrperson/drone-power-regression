# Drone Power Consumption — Regression Analysis

ISYE 6414 (Regression Analysis) final project, Georgia Institute of Technology.

## Overview

We model electrical power consumption (`Power = Voltage × Current`) of a DJI Matrice 100
quadcopter in flight, using the Carnegie Mellon in-flight telemetry dataset (250,000+
timestamped readings across 209 flights). Two independent modeling approaches were used to
deal with heavy within-flight autocorrelation in the raw data:

| | **Stepwise** | **LASSO** |
|---|---|---|
| Data reduction | 3 phase-sampled points/flight (n=628) | Per-flight average (n=209) |
| Selection | Bidirectional stepwise | 10-fold CV, λ_min |
| Final predictors | 8: payload, velocity_z, linear_acceleration_z, orientation (x,y,z), flight_phase | 4: wind_speed, wind_angle, velocity_z, payload |
| Adjusted R² | 0.85 | 0.41 |
| Out-of-sample RMSE | 91.51 W | 38.61 W |
| Best used for | Explanatory power | Predictive accuracy |

**Bottom line:** payload mass and vertical velocity (z-axis) are the most consistent drivers
of power draw across both approaches; wind speed/angle matter too. See
`report/Project_Report.pdf` (Section 7, Conclusions) for the full writeup.

## Reproducing the analysis

Scripts assume they're run **from the `scripts/` directory** (they use `../data/...` relative
paths) and require R with these packages:

```r
install.packages(c("readr", "dplyr", "car", "corrplot", "lmtest",
                    "glmnet", "pwr", "sandwich", "lmtest"))
```

Run order:
1. `scripts/lasso_approach.R` — reads `data/raw/flights.csv`, derives `power_consumption`,
   averages per flight, writes `data/processed/flight_avgs.csv`, then fits/validates the
   LASSO model.
2. `scripts/stepwise_approach.R` — expects a phase-sampled `data/processed/drone_data.csv`
   (628-row, 3-observations-per-flight extract used for the stepwise model). This file isn't
   included; it's produced by the phase-sampling step described in the report/proposal — you'll
   need to add that preprocessing step if you want to regenerate it from `flights.csv`.

## Recommendations / things worth doing next

- **Git LFS for `flights.csv`** (~67 MB) — GitHub's soft limit is 50 MB per file before it
  warns, and 100 MB is a hard block. Track it with LFS or keep it out of git entirely and
  document how to fetch it (see `.gitignore`, which currently excludes it).
- **Commit `flight_avgs.csv` and the phase-sampled `drone_data.csv`** as the canonical
  processed datasets, so the R scripts are reproducible without re-deriving them — right now
  `stepwise_approach.R` depends on a file that isn't in the repo.
- **Pin package versions** with `renv` (`renv::init()`) so `glmnet`/`car`/etc. don't drift and
  break the diagnostics later.
- **Remove `install.packages()` / `remove.packages()` calls from the top of scripts** — these
  force reinstalls on every run. Better: a single `requirements.R` or `renv.lock` that's
  installed once.
- Consider splitting `lasso_approach.R` into two scripts (data prep vs. modeling) since it
  currently does both.
